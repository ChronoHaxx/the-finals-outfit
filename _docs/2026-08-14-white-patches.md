# White patches: black garments bake white

> **Amended 2026-08-15.** Every figure below is the *pre-fix* measurement and is
> kept as the record of what was wrong. It is no longer the current state, and
> the corpus has changed underneath it: this document counts **1,968** albedos,
> while the catalogue now bakes **2,474**. Do not reconcile the two by
> arithmetic — they are different corpora, and no bake metadata survives to say
> which items joined when.
>
> Current state lives in `2026-08-15-white-patch-scan.txt`, regenerated by
> `npm run scan:white-patches`: **40 flagged of 2,474**, of which 36 are
> confirmed legitimate against a catalogue icon and 4 are unverifiable because no
> icon exists. That report is derived; this document is history.

96 of 1,968 baked albedos carry near-white blobs on garments that should be dark.
`racing-helmet-carbonfiber` renders as a white helmet with black blotches; it
should be black carbon weave with an orange LED visor.

This is baked into the texture, not a lighting or shading problem — it survives
`?debugAlbedo=1`, which draws raw albedo with no lighting at all.

## Mechanism — confirmed, not inferred

`scripts/bake-composite.mjs` decides a layer's colour like this:

```js
let col = p.baseOverlay;
if (ovMin > 0.85 && p.baseColorMaskStrength > 0 && !schemeIsPlaceholder) {
  col = mix3(col, schemeColor(mask, mi), p.baseColorMaskStrength);
}
```

A layer authored as **near-white with `BaseColorMaskStrength = 1`** means "I am a
blank surface, tint me from the scheme". If `schemeIsPlaceholder` is true the
tint is skipped and the layer stays white.

`schemeIsPlaceholder` is true only when **all three** of ColorA/B/C fail
`isPlaceholderSwatch`, which rejects a swatch that is near-white, **near-black
(`max < 0.05`)**, or a pure saturated primary.

The racing helmet's own values:

```
ColorA  rgb(0.010, 0.010, 0.010)   near-black  -> rejected as placeholder
ColorB  rgb(0.000, 1.000, 0.000)   pure green  -> rejected as placeholder
ColorC  rgb(0.000, 0.000, 1.000)   pure blue   -> rejected as placeholder

L1 BaseColorOverlay rgb(1,1,1)  BaseColorMaskStrength 1   -> stays white
L2 BaseColorOverlay rgb(1,1,1)  BaseColorMaskStrength 1   -> stays white
```

**ColorA is not a placeholder. It is the helmet's actual colour.** The proof is
that the other rendering path reads the same value and emits
`regionColors: ["#1a1a1a", "#1a1a1a", "#393939", "#1a1a1a"]` — correct black.
The two paths disagree about the same source data and the baked one is wrong.

**So the defect is the near-black test.** `max < 0.05` treats a legitimately
black garment as unset. Black is a real and extremely common colour in this
game — carbon fibre, leather, tactical gear — and the test throws it away.

## The trap: do not simply delete the test

That guard exists for a real case, named in the source comment: a dark overlay
blended toward a red/white placebo scheme baked the SentinelTop pauldrons white.
Removing the placeholder logic re-opens that. Two distinct situations have to
stay distinguishable:

- **A genuinely unset scheme** — the engine's default palette, where blending
  toward it destroys a real authored overlay.
- **A deliberately black scheme** — a black garment, where the value *is* the
  intent.

The near-white and pure-primary tests look defensible. It is specifically the
near-black one that cannot distinguish "unset" from "black", and black is not a
plausible default in a palette whose other defaults are pure red, green and blue.

**Consider whether the judgement should be per-swatch rather than all-or-nothing.**
Here ColorA is real while ColorB and ColorC are placeholders; the current code
collapses that to a single boolean and then discards all three. A scheme where
only ColorA carries meaning is common — and `schemeColor()` already blends A→B→C
by mask channel, so an unused B or C simply never gets selected.

## Scope

- **96 of 1,968** distinct baked albedos have a near-white region on an otherwise
  dark garment (>0.5% of pixels above 245 on all channels, mean brightness < 170).
- Worst offenders are 40–47% white: `racing-helmet-carbonfiber`,
  `sport-cleats-nylon-yellowblackv2`, `military-tacticalboots-base-arenasecurity`,
  `streetwear-largesneakers-rubber-cb2a`, `ninja-shinobijacket-cotton`.
- The detector is a heuristic and **will contain false positives** — a genuinely
  two-tone black-and-white shoe looks the same to it. Verify against the icon
  before treating any single item as broken.

## Constraints

- `npm run dev` must be running for renders.
- Do not retune `MIN_STDDEV`, `PATTERN_STRENGTH`, `AO_STRENGTH`, or any tuning
  constant. The defect is a classification rule, not a magnitude.
- Do not change the region-tint path. It already produces the right answer and is
  the evidence that the source data is fine.
- Baked textures are gitignored generated output; re-baking is safe.
