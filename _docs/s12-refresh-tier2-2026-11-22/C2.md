There were no console errors in any shot. Three first attempts are kept as recorded and marked invalid in `REPORT.md`:
- **The first idle sets came out still.** `serve-preview.mjs` needs `--animations-base` (the deploy's
  ANIMATIONS_BASE) for idle and emote clips. Without it, `anim=outfit-idle` finds no clip and the page stays in the
  still pose. Both sets were re-shot with it, and the idle frames differ from the still ones.
- **The first Light set captured Medium.** `capture-review.mjs` opens `?outfit=1.<json>` links, and that route reads
  the archetype only from the outfit itself. `ar=` belongs to the short links (`o=`, `look=`), so `--query "ar=l"`
  alone captures Medium.
  - `capture-review.mjs` now takes `--archetype light|heavy`, which puts the archetype in the outfit. Without the
    flag, the URL is unchanged.
  - Check a Light set by its shot records: the meshes must be the `_L` ones.
